## 0. 总体流程（初版是怎么做出来的）

初版是按下面的顺序一步步做出来的，每一步都尽量让后面的步骤有据可依：

| 阶段 | 做了什么 | 产出 |
| --- | --- | --- |
| 1. 读策划案 | docx 本质是 zip，解压后用 Python 解析 `word/document.xml`，把段落和表格提取成纯文本，逐条整理需求清单 | 需求清单（见 1.1） |
| 2. 定技术方案 | 选 TypeScript + three.js，用 esbuild 打包成单个 IIFE 脚本，再内联成一个 HTML 文件；决定所有美术和声音都用代码生成 | `package.json`、`build.mjs`、`serve.mjs` |
| 3. 先写数据与规则 | 把策划案里所有表格搬进 `config.ts`；写子弹目录、枪械生成公式、道具表 | `src/config.ts`、`src/data/` |
| 4. 写纯逻辑层 | 地图生成、碰撞、寻路流场、敌人、投射物、玩家、Boss、背包、商店、整体流程。逻辑层不依赖 three.js，可以直接在 Node 里跑 | `src/world/`、`src/game/` |
| 5. 无头模拟 + 自动 AI | 写一个自动游玩的 AI，在 Node 里批量跑对局，用数据找 bug、调数值（第一轮平衡） | `tools/sim.ts`、`src/debug/bot.ts` |
| 6. 渲染、音频、界面 | 程序化贴图与模型、实例化丧尸、粒子、灯光与后期；WebAudio 合成音效与音乐；HUD、背包拖拽、安全屋、菜单 | `src/render/`、`src/audio/`、`src/ui/` |
| 7. 浏览器联调 | 本地服务器 + 内置浏览器截图检查画面；调试参数（`?bot=1`、`?zone=3`、`?god=1`）快速跳到想看的场景；修画面和交互 bug | 各类修复 |
| 8. 补充与第二轮平衡 | 补上策划案提到但没定义的「逻辑模块」、小窗口界面缩放、尸体倒地等；再跑模拟调整难度 | 初版 |
| 9. 文档 | README（项目简介、游玩与开服）、CONTRIBUTING（组员协作指南）与本文档 | `README.md`、`docs/开发流程.md` |

第2版的流程见 1.8（设计）、2.4（联机实现）与更新日志；第3次调整见 1.9。

## 1. 设计

### 1.1 把策划案拆成需求清单

先把策划案逐句拆成可检查的条目，例如：

- 操作：WASD、鼠标瞄准、左右键对应主副手、TAB 背包、ESC 暂停（初版 TAB 背包不暂停；第2版改为打开背包同时暂停）。
- 背包：16 单位；金币每 1750 占 1 单位；装在枪里的子弹单独储存；拖出界面丢弃；拾取时图标闪烁；`x/x` 显示，剩余 ≤5 橙色、0 红色。
- 刷怪：初始少量均匀分布；摄像机外持续生成并随周围密度调速；类型权重池 + 临近降重；精英优先、保底 10/14/18/22 个。
- 敌人表、区域倍率、生成权重、变异概率、辐射阈值、道具表、祭坛表、商店规则……

所有表格原样写进 `src/config.ts`，并用注释区分「策划案原值」「第2版」和「自定」的参数，方便以后核对。

### 1.2 策划案中有歧义的地方，以及我的解读

| 问题 | 我的处理 | 理由 |
| --- | --- | --- |
| 子弹属性里的 `Rng` 是什么 | 普通子弹表示弹丸大小（命中半径 = Rng × 0.06 米）；炸弹、地雷等表示爆炸范围的**直径** | 炸弹例子写「对 9 米范围内造成伤害」，按半径 9 米理解会大到失衡 |
| 辐射值的单位 | 强化系数 `log10(辐射值) − 0.5` 中的辐射值以 K 为单位 | 如果用原始数值（16000），第一区系数就有 3.7，明显不合理；用 K 计算时第一区恒为 1，第四区约 1.6，曲线合理 |
| 「伤害随区域乘区变化」 | 额外设定区域伤害乘区 1.0 / 1.15 / 1.3 / 1.45 | 策划案提到但没给数值；最初取 1.0/1.25/1.5/1.8，测试后发现后期太致命而下调 |
| 安全屋在哪、下一区往哪延伸 | 安全屋位于区域顶部角落；出口随机在左上或右上，出口方向决定下一区向左还是向右展开 | 对应「每次进入安全区时随机设定左上角或右上角为新区域起点入口」，整条路线形成一条向上的折线 |
| 「场上精英不少于 N 个」 | 按全图计数；区域开始时的精英分散在全图，之后阵亡的精英才在玩家附近立即补充 | 一开局就在玩家身边刷出 10 个精英，测试中几乎必死 |
| 背包描述里的「逻辑模块」 | 设计成类 Noita 的修饰法术（见 1.5） | 策划案只提到名字，没有定义 |
| Boss 区的数值 | 用第 4 区的敌人构成，但刷怪更少。初版的防护服阈值设为 170/200/215K；第2版按改动文档固定为 240K；第3次调整改为 V 级防护服的 0/200/240K（见 1.9） | 策划案只给了 4 个区域的表格 |

### 1.3 枪械设计

**公式**（第2版改动文档；初版为 `×1.65×(0.8~1.2)`、散射 0~360°）：

```
(稀有度 + 2) × 1.75 × (0.7~1.4) = 攻击倍率 × (1/射击延迟) × (1/换弹延迟) + 最大载弹量
```

约束：载弹 2~10，射击延迟 ≤ 0.40s，换弹延迟 ≥ 0.40s，散射 −40~40°，攻击倍率 ≥ 0.50x。稀有度权重（地图与商店相同）：1 区 50/40/10/0、2 区 30/40/20/10、3 区 20/30/30/20、4 区 10/20/40/30。

**生成算法**（`src/data/guns.ts` 中的 `makeGun`）：

1. 先算出总预算 `B = (稀有度+2) × 1.75 × 随机(0.7~1.4)`。
2. 载弹量从 2 到 `min(10, B−1)` 之间取，偏向中间值；剩余预算 `R = B − 载弹量`，也就是 `攻击倍率 / (射击延迟 × 换弹延迟)` 必须等于 R。
3. 拒绝采样：在 [0.06, 0.40] 里对数均匀地取射击延迟，在 [0.5, 4.5] 里对数均匀地取攻击倍率，再由公式反推换弹延迟；换弹落在 [0.4, 2.6] 内就接受，最多尝试 60 次，失败时用保底值。这样所有枪都严格满足公式。
4. 散射：第2版在 −40~40° 之间均匀随机。**负散射**的含义我定为「抵消子弹自带的散射」：发射时用「枪械散射 + 子弹数值补正 + 子弹额外散射 − 聚焦模块」之和，再截断到 0~360°，所以一把 −30° 的枪可以把鹿弹（+40°）收拢成 10° 的扇面。初版用 `360 × u^(4+稀有度)`，这里保留记录以便对比。
5. **命名规律**（第2版「所有的枪械名称和数据在一局中依照某种规律随机生成」）：
   - 名称 = 代号 + 类别。代号词库按稀有度分四档（R1「打工人、保温杯、拖拉机……」，R4「黑曜石、断头台、审判日……」），一看名字就能猜出档次。
   - 类别完全由数据决定：射击延迟 ≤0.1 且载弹 ≥6 → 转轮机枪；攻击倍率 ≥2.6 且延迟 ≥0.28 → 榴弹发射器；散射 ≥25° → 霰弹枪（载弹 ≤3 叫喷子）；延迟 ≤0.12 → 冲锋枪；攻击倍率 ≥1.8 或散射 ≤−25° → 狙击枪；载弹 ≤3 → 手枪；载弹 ≥7 → 轻机枪；其余按换弹快慢分卡宾枪 / 步枪。
   - 型号 = 类别代码 + 厂商字母 − 稀有度 + 载弹量，例如 `SMK-47` = 冲锋枪、K 厂、Rarity4、7 发（10 发记作 0）。开局武器也按这个规律改名为 `HGK-13 老伙计手枪`、`SGB-12 拆迁办短喷`。
6. 外观也由数据决定：攻击倍率越高枪管越长，载弹 ≥7 用弹鼓，散射大的枪口加宽，攻击倍率高的加瞄准镜，稀有度决定发光条颜色。

**这个公式带来的特点**（推导后用抽样验证）：每秒伤害约正比于 `(B − 载弹量) × √(载弹量 × 射击延迟 × 换弹延迟)`，所以「慢而重」的枪单发伤害高，「快」的枪换弹时间长，这是公式自带的取舍。第2版的系数平均比初版高约 11%，随机范围也更宽，同稀有度的枪差距更大。高稀有度的主要优势是槽位更多，可以装更多子弹和模块。

**开局武器**：手动挑选数据，但仍代入公式计算（随机系数取 1.2 和 1.15）：主手「老伙计手枪」（3 槽：标准弹×2 + 黄铜弹），副手「拆迁办短喷」（2 槽：鹿弹）。副手原本装的是三发弹丸，但它的后坐力会让玩家减速 33%，比丧尸还慢，所以换成了鹿弹。

### 1.4 子弹设计

策划案只给了两个例子（三发弹丸、炸弹），其余由我设计。设计思路是让每种子弹代表一种明确的玩法，并且互相能组合：

| 定位 | 子弹 |
| --- | --- |
| 基础单体 | 标准弹、穿透型黄铜子弹（穿 3）、重型铅弹（击退）、钨芯穿甲弹（穿 10、射程 42 米） |
| 散射清群 | 三发弹丸、鹿弹（7 发近程）、环形弹幕（360° 12 发） |
| 范围伤害 | 炸弹（2.5 秒引信）、三级火箭（逐级加速、碰撞爆炸）、感应地雷、毒雾弹、奇点弹（吸引后坍缩） |
| 特殊轨迹 | 弹跳弹（墙面与敌人间反弹）、追踪飞镖、分裂弹、圆锯片（持续切割）、回旋镖（往返）、等离子射线（无限穿透） |
| 状态效果 | 燃烧弹（会传染）、液氮弹（减速）、电弧弹（连锁闪电） |
| 功能型 | 轻量化弹头（加快射速与换弹）、吸血弹（回血）、招财弹（金币 +60%）、喷射推进弹（几乎无伤害，用巨大后坐力当冲刺） |

每种子弹包含：

- **基础数值**：攻击、弹速、大小、额外散射、后坐系数。生成实例时每项各自随机 0.7~1.4 倍；界面用颜色标出每项的「手气」，高于 112% 绿色、高于 128% 金色、低于 82% 红色。第2版起**散射一栏反过来**：散射是坏属性，带正散射的子弹显示为红色（偏移越大越红），负散射的子弹偏移越大越绿。
- **闪耀 / 虹彩**（第2版）：每枚子弹生成时分别判定 20% 闪耀（攻击 ×1.25）与 5% 虹彩（攻击 ×1.6），可以同时出现（×2.0）。所有来源都适用：地图、商店、枪里自带、精英掉落、开局武器。逻辑模块没有攻击力，不参与判定。
- **数值补正**：装进枪后修改枪的射击延迟、换弹延迟、散射。例如三级火箭 +0.30 射击延迟 / +0.30 换弹延迟，轻量化弹头 −0.06 / −0.12。
- **特效**：穿透、爆炸、追踪等，在 `projectiles.ts` 里按类型模拟。

**数值的演变**：初版标准弹攻击为 28。第一轮模拟发现初始武器杀一只普通丧尸要 5 枪左右，敌人越积越多，于是整体 ×1.4（标准弹 40），后来又 ×1.5（标准弹 60）。策划案原例中三发弹丸攻击 12、炸弹攻击 140，它们的机制按原例实现，但攻击力在这两轮调整中分别变成了 24 和 210。弹速统一乘 0.45 换算成米/秒（例如标准弹 70 → 31.5 m/s），否则子弹快到看不见。

### 1.5 逻辑模块（对「逻辑模块」的补充设计）

模块装在枪的子弹槽里，**本身不射出子弹，也没有后坐力**，作用于排在它后面的子弹，规则参考 Noita：

- 双重 / 三重施放：接下来的 2 / 3 发子弹同时射出；
- 追踪、穿透（+3）、爆裂（命中时 2 米小爆炸，60% 伤害）、增幅（伤害 ×1.6）、加速（弹速 ×1.8，伤害 ×1.15）、聚焦（散射 −60°）。

射击循环中：遇到模块就累积效果并立刻跳到下一格，遇到真正的子弹时把累积的效果作用在它身上并射出；多重施放会让「待射出数量」增加，所以同一帧可以连续射出多发。模块数值不随机，只带少量数值补正。随机掉落时约 14% 的概率出现模块。

### 1.6 后坐力

完全按策划案公式：`实际后坐 = (1/射击延迟) × 后坐系数`，小于 15 时移速降低 `(R/15)²`，15~30 时持续向后推 `(R−15)/2` 米/秒，大于 30 时冲力位移 `(R−30)/2` 米。界面显示策划案里的三个标签【轻松射击】【太空步】【肩胛粉碎者】。补充了三个上限：减速最多 85%（接近 15 时公式会给出 90% 以上，几乎走不动），推力最多 7 米/秒，单次冲刺最多 8 米。下盘功夫的减免作用在实际后坐值上，所以有可能把一发子弹从高档降到低档。

### 1.7 平衡迭代（数据驱动）

平衡主要依靠无头模拟（见第 5 节），关键的几次调整：

| 发现 | 调整 |
| --- | --- |
| 策划案中社畜丧尸速度 4.6 > 玩家 4.0，玩家完全没法拉扯 | 丧尸移速统一 ×0.62，后来再降到 ×0.58 |
| 初始武器每秒约杀 0.25 只，开局 20 秒内周围就堆满 80 只 | 子弹伤害两次上调；初始刷怪数 90 → 24；刷怪速度改为开局较缓、随后加压 |
| 被包围时伤害太集中 | 丧尸贴身 0.3 秒后才出手，每只冷却 1.2 秒，玩家受击后无敌 0.25 → 0.5 秒 |
| 头铁丧尸（700 血、第一区占 28%）消耗了大部分火力 | 保留策划案数值，但调低各区「周围敌人过多」的阈值（第一区 85 → 34），让敌人数量随玩家实力逐区增加 |
| Boss 战中大部分伤害来自 Boss 区的小怪 | Boss 区刷怪 1.6 → 0.9 只/秒，精英保底 8 → 4，召唤从 6 只橙/红精英改为 5 只黄/橙精英，冲刺蓄力 0.88 → 1.0 秒 |
| AI 即使只承受 50% 伤害，在普通难度下也大多倒在第一、二区 | 难度重新分档：普通 = 敌人生命与伤害 ×0.8、刷怪 ×0.9；困难 = 策划案原始数值；另有简单与噩梦 |
| （第2版）自己的子弹也会造成 5% 伤害后，单人 AI 有一半死因是「自伤」：站在自己的毒雾里、贴脸打火箭，以及感应地雷（扔在脚边、被追来的丧尸触发，半径 4 米的爆炸每次给自己 33 点伤害） | 保留 5%，但爆炸的友伤随距离衰减（中心 5% → 边缘 1%），并给友伤单独 0.5 秒无敌；AI 学会避开自己的毒雾、快爆炸的炸弹，不在贴脸时打出爆炸类子弹（模拟真人的做法） |
| （第2.1版，用户建议）感应地雷仍然容易炸到自己 | 地雷被敌人触发后延迟 0.5 秒才爆炸（指示灯快速闪烁并发出提示音），玩家有时间离开 |
| （第2版）联机时丧尸只按人数加血，每个人分到的丧尸（和金币）太少 | 刷怪速率与上限再乘 1.2/1.4/1.6，精英保底每多一人 +15%（详见 1.8） |
| （第3次调整）连续投石最初的预警只有 0.55~0.85 秒，以初始移速（4 米/秒）一直跑也躲不开 2.8 米的命中半径 | 预警到砸落改为 0.72~1.05 秒（原来 0.95~1.45 秒）：一直跑动刚好能躲开，站着不动必中；曼巴的大石块（命中半径 4 米）0.85~1.15 秒。改后 Boss 测试中 AI 几乎不再被石块砸中，主要死因回到小怪和冲刺 |

最终模拟结果（第2版）：单人普通难度 AI 约 40% 能进入第二区（与初版持平）；简单难度 8 局通关 2 局，其余分布在各个区域。3 人联机简单难度可以通关。AI 的走位明显不如真人，所以真人体验应该比这些数据好，但仍需要真人试玩确认。

第3次调整后（数值按文档实现，没有额外补偿）：
- 普通难度 10 局里仍有 4 局进入第二区（第一区的强化系数恒为 1，与原来的区域值相同）。

## 2. 代码

### 2.1 技术选型

- **TypeScript**：代码量大，需要类型检查兜底（`npm run typecheck` 全程零错误）。
- **three.js**：成熟的 WebGL 3D 库，支持实例化渲染、阴影、后期。
- **esbuild 打包成 IIFE**：浏览器用 `file://` 打开 HTML 时不能加载 ES 模块，所以打包成普通脚本，再由 `build.mjs` 把脚本内联进 `Game4056.html`，双击即可玩；CSS 用 esbuild 的 text loader 打进脚本，运行时再插入页面。
- **字体裁剪**（第2.1版）：`build.mjs` 每次构建时扫描 `src/` 里出现的所有字符，用 `subset-font`（harfbuzz 的 wasm 版）把像素字体裁成只含这些字符的 woff2，再以 base64 写进页面的 `@font-face`。以后改了界面文字，重新构建就会自动带上新字，不需要手工维护字表。第3次调整后裁剪的是合并字体 `assets/fonts/pixel4056.ttf`（由 `tools/merge-font.py` 用 fontTools 生成，见 3.5）；构建本身仍然只需要 Node。
- **联机（第2版）**：浏览器之间不能直接互连，所以由房主电脑上的 Node 服务器转发。为了不给玩家增加安装步骤，WebSocket 协议（握手、帧的解析与封装、分片、ping/pong）在 `serve.mjs` 里按 RFC 6455 手写，不依赖任何第三方库。

### 2.2 架构

```
config / data  ── 纯数据：策划案表格、子弹与模块目录、枪械公式、道具
     │
world / game   ── 纯逻辑（不依赖 three.js，可在 Node 中无头运行）
     │   World.update(dt) 每秒固定 60 次
     │   通过 Fx 接口发出「开枪了」「爆炸了」「播放某音效」等事件
     │   通过 NetHooks 接口发出联机消息（单人时为 null）
     ▼
net            ── 联机：Transport（WebSocket / 内存中转）+ Coop（实现 NetHooks，收发与分发消息）
render / audio / ui ── 表现层：读取 World 状态并绘制；实现 Fx 接口
     │
app.ts         ── 状态机（主菜单 / 游戏中 / 暂停 / 结算）、主循环、输入分发、联机房间
serve.mjs      ── 静态文件 + 房间服务 + 消息转发
```

逻辑和表现分离是整个项目最重要的决定：同一套游戏逻辑既能在浏览器里玩，也能在 Node 里由 AI 每秒跑上千帧做平衡测试（测试时传入空实现的 `nullFx`）。第2版沿用了这个思路：联机逻辑只通过 `NetHooks` 接口与游戏逻辑交互，传输层可以替换成内存中转，于是多个 AI 玩家可以在一个 Node 进程里联机对战（`tools/mptest.ts`）。

### 2.3 关键实现

- **地图生成**（`world/zone.ts`）：每区 104×136 米，先划 4×5 的街道网格，每个街区随机定成废墟、高楼、停车场、公园、碎石场、工业区、广场之一（不同区域权重不同，比如第二区多工业区）。废墟的外墙切成高低不一的段，至少留 2 个门洞并随机坍塌缺口，保证可以进出；街道上随机摆车辆残骸、路障、碎石、油桶，但不会完全堵死。起点角和安全屋入口所在的街区固定为空旷广场。安全屋房间的墙、门、设施（祭坛、商店、第2版新增的防护服柜、第3次调整新增的医疗箱）作为对象被下一区复用，过渡时不会出现跳变。第3次调整：尸王广场顶部看台中间留出缺口，后面是一间上锁的「简易安全屋」（只有医疗箱）；第六区「隐秘核心」用同一个场地生成函数，柱子更多、内圈有 4 根矮柱。
- **碰撞**（`world/collision.ts`）：障碍物都是轴对齐盒子，放进 4 米网格做空间索引；角色是圆，与盒子求最小推出向量，最多迭代 3 次；子弹用线段与盒子求交（slab 法），高度低于 1 米的掩体（沙袋、路障）挡人但不挡子弹。
- **寻路流场**（`world/navgrid.ts`）：1 米网格，障碍膨胀 0.35 米后标记为不可走；每 0.25 秒做一次 Dijkstra（直线代价 10、斜线 14，用二叉堆），每只丧尸只需查看所在格的 8 个邻格，就能沿下降方向走向玩家。第2版改成**多源**：所有可以追击的玩家同时作为起点，一次计算后每只丧尸自然走向离它最近的玩家，计算量与单人相同。
- **敌人空间哈希**（`util/spatial.ts`）：2 米网格，每帧重建，用于分离推挤、子弹命中、爆炸范围、类型判别时统计附近同类。
- **刷怪**（`game/enemies.ts`）：每秒刷怪数 = 基础值 × 难度 × 时间爬升 × 密度系数（玩家 26 米内敌人过少时 ×1.8，过多时 ×0.15）× 联机人数倍率。联机时对每名玩家分别计算密度，刷怪点按「谁身边缺怪」加权选择，并且离所有玩家都在 28 米以外。类型判别时，附近 12 米内每有一个同类，该类权重 ×0.72。精英不足保底时立即一次性补齐。距离最近玩家超过 50 米的非初始敌人会被回收到玩家附近。
- **投射物**（`game/projectiles.ts`）：子弹很快，逐帧检测会穿透目标，所以每帧用「移动线段 vs 敌人圆」做扫掠检测，并按命中先后排序处理穿透；炸弹、地雷、锯片、回旋镖、毒雾、奇点各自有简单的物理模拟。第2版每个投射物记录发射者，同样用扫掠检测玩家（友伤），命中玩家比命中墙和丧尸更早时截断本帧的移动。
- **拾取**（`game/pickups.ts`）：地面物品有「经过自动拾取」和「需要按 F」两种；联机时非房主先向房主申请，房主确认后才放进背包（期间背包被占满则丢回脚下）。地图道具的编号由「区域 × 1000 + 序号」决定，各玩家用同一个种子生成，编号天然一致；玩家丢下的物品编号为「(玩家编号+1) × 100 万 + 计数」，不会冲突；收到别人丢下的物品时重新分配本地的背包编号。
- **Boss**（`game/boss.ts`）：状态机 `出场 → 追击 → (肘击蓄力 → 冲刺 → 恢复/撞墙眩晕) 或 (举石 → 连续投石)`。第3次调整：4 个阶段，3/4 和 1/4 血量时召唤，半血以下狂暴；连续投石每块都重新锁定目标。预警线和落点圈作为数据交给渲染层绘制。第2版追击最近的玩家，冲刺途中保持原目标，接触冷却按玩家分别计算；非房主的 Boss 是只接收状态的镜像。
- **曼巴僵尸**（`game/mamba.ts`，第3次调整）：和牢大实现同一个 `BossAI` 接口（世界、联机、渲染只认这个接口）。状态机如下，每损失 1/5 生命召唤 8 只精英，半血狂暴：
  - `追击 → 冲撞蓄力 → 冲撞（狂暴后连冲 3 次）`
  - `举石 → 连续投石`（命中半径 3.6 米，牢大为 2.4 米）
  - `激光蓄力 → 旋转激光`（2 道，狂暴 3 道；光束长度每帧用射线检测被柱子截断）
  - `冲击波蓄力 → 冲击波`：任何时候有玩家贴近到约 7 米就打断其他计划，即使玩家处于无敌时间也会被推开
  - 激光和冲击波也是「预警」数据（`beam` / `ring`），带旋转角速度和「跟随 Boss」标记，所以镜像端在两次状态同步之间能自己转动激光。
- **背包与商店**（`game/inventory.ts`、`game/shop.ts`）：每个操作都是纯函数，成功返回 `null`，失败返回原因文字（如「背包空间不足」），界面直接拿来弹提示。第4.1次调整：物品可以在“背包”和“临时整备区”两个容器之间移动，操作函数都带上容器参数。
- **施放顺序**（`data/guns.ts` 的 `castOnce`，第4.1次调整）：开枪和 DPS 估算共用同一个函数，按槽位顺序取出一次施放要射出的子弹（逻辑模块累积到下一发、多重施放、复制、熔炼、循环），开枪时再处理盲盒的随机变化。
- **区域任务**（`game/quest.ts`，第4.1次调整）：生成每个区域时、在构建碰撞与导航之前放置任务物件（可燃物堆作为障碍物加入地图），用临时的导航网格从起点做一次洪泛，保证目标都能走到。任务的随机数由区域种子派生，所有玩家一致；宝箱和异变体只由房主生成。渲染在 `render/questView.ts`。
- **奇物**（`data/relics.ts`、`game/relicfx.ts`、`ui/relic.ts`，第4.1次调整）：攻击倍率类增益在 `RunState.atkBonus()` / `handStats()` 里统一计算（全局强化零件1型、过热模块也在这里），HUD、背包、提示框和开枪都读同一个结果。

### 2.4 联机实现（第2版）

**房间**（`serve.mjs`）：房主「创建房间」得到 4 位随机字母的房间号；其他人「加入」后进入大厅（最多 4 人，编号 0~3 同时决定标识颜色）；房主选难度和种子后「开始」，服务器把种子、难度和玩家列表发给所有人。游戏中的消息格式是 `{t:'r', to, d}`，`to` 为 −1（其他所有人）、−2（房主）或指定玩家；二进制消息的第一个字节是目标，服务器转发时替换成发送者编号。房主断开时房间解散；一局结束后房主可以把房间重置回大厅。`/api/info` 返回本机的局域网地址，大厅里直接显示给房主看。

**确定性的部分**：所有人用同一个种子生成地图，流程函数（开局、进入安全屋、离开安全屋）在每个人的电脑上按同样的顺序调用同样次数的地图随机数，所以地图、安全屋、地面道具在所有人那里完全一致，不需要传输。只有房主的消息能推进流程（`ph` 消息：safe / leave / boss / door / victory / over，第3次调整加入 core = 牢大倒下且打开隐秘核心）。第五区安全屋里的净化血清也是所有人按相同编号（5000 + 序号）在本地生成的。

**同步的部分**（`net/coop.ts`）：

| 内容 | 方向 | 频率 / 方式 |
| --- | --- | --- |
| 玩家状态（位置、速度、朝向、生命、倒地、阵亡、是否已进安全屋、防护服、开火与换弹动作、暂停、击杀数、拉起进度） | 每人 → 所有人 | 每秒 20 次；其他人在本地按速度外推并平滑 |
| 枪械外观 | 每人 → 所有人 | 换枪时 |
| 丧尸快照（编号、类型、变异与燃烧/减速状态、位置、速度、朝向、生命、生命上限） | 房主 → 所有人 | 每秒 20 次，二进制，每只 28 字节；400 只丧尸约 11 KB |
| 射出的投射物 | 每人 → 所有人 | 每帧合并；其他人生成「影子子弹」，只用于显示和友伤判定 |
| 对丧尸造成的伤害、击退、燃烧/减速/招财标记，奇点吸引 | 非房主 → 房主 | 每帧合并 |
| 击杀（含击杀者，用于 100% / 25% 金币）、口水弹与石块、表现事件（横幅、音效、震屏） | 房主 → 所有人 | 每帧合并 |
| 被丧尸 / Boss / 苦力怕打中（第4.1次调整：由被打的人本地判定） | 被打的人 → 房主 → 所有人 | `hu`：房主让那只丧尸进入出手冷却；`hf`：其他人播放受伤表现 |
| 区域任务进度（发送信号进度、已点燃的火堆、物资球位置、净化比例、是否完成） | 房主 → 所有人 | 随流程信息每秒 10 次；非房主点燃火堆（`qi`）、踢球（`qk`）先在本地生效再交给房主 |
| 超级防护服平分辐射（`ra`） | 房主 → 所有人 | 进入安全屋时 |
| 拾取申请与结果、丢下的物品、拉起队友、暂停 | 按需 | 即时 |
| 流程倒计时、等待提示、Boss 状态与预警（第3次调整：预警带类型、旋转角速度和是否跟随 Boss，两种 Boss 共用一种格式） | 房主 → 所有人 | 每秒 10 次 |

**非房主的丧尸**是「镜像」：按快照创建、更新、删除，位置用「快照位置 + 速度 × 经过时间」外推，再以指数平滑靠近（误差超过 3 米直接跳过去）。自己的子弹在本地命中镜像丧尸时立刻扣血、闪白、出伤害数字，同时把伤害发给房主；本地血量降到 0 时先把它隐藏 0.6 秒等待房主确认，如果房主没有确认就恢复。快照里的血量只取较小值，因此不会因为消息先后顺序出现「回血」。

**受击判定**：口水弹和石块在每个人本地模拟，由被打的人自己判定（躲开就是躲开了）。接触攻击原来由房主用远程玩家的位置判定，第4.1次调整改为同样由被打的人在本地判定：每个人用自己看到的丧尸镜像位置计算碰撞（贴身 0.3 秒后出手、每只冷却 1.2 秒），苦力怕在收到击杀消息时判定是否被炸到，Boss 的接触、冲刺、激光和冲击波由镜像端的 `mirrorHits` 判定。丧尸的攻击力按与房主相同的公式在本地计算（快照里有类型、变异等级和异变体标记）。

**暂停**：每个人把「是否暂停」（ESC 菜单或打开背包）放进状态里，任何一人暂停时所有人都停止模拟，屏幕上显示「xxx 玩家正在暂停游戏」。安全屋里没有敌人，此时暂停不起作用。

**页面在后台时**：浏览器会停掉后台页面的 `requestAnimationFrame`，而房主一停，所有人的丧尸都会冻住。所以联机时另开一个 Worker 计时器（每 33 毫秒），一旦超过 0.2 秒没有画面帧，就只做模拟和收发消息。测试时发现内置浏览器的后台标签页会停掉画面帧，但 `document.hidden` 仍然是 false，所以判断条件用的是「多久没有画面帧」而不是页面可见性。

**带宽**（无头测试实测）：4 人对局时房主上行约 60 KB/s，其他玩家约 3.5 KB/s，局域网绰绰有余。

## 3. 美术

所有美术资源都在运行时用代码生成，没有下载或引用任何图片、模型文件。这样做是因为：不用担心素材版权；单个 HTML 就能离线运行；外观可以直接由游戏数据驱动（比如枪的外观来自它的属性）。

### 3.1 贴图（`render/textures.ts`）

用 Canvas 2D 画，再转成 three.js 贴图：

- 基础手法：随机噪点、径向渐变的污渍、随机折线画的裂缝。
- 混凝土 / 医院白墙 / 红砖墙（砖块逐块随机明暗）、带窗户的高楼外立面（少数窗户亮灯，另配一张自发光贴图）、集装箱的波纹金属、木箱、警示条纹、安全屋金属墙板。
- **整张地面贴图按地图数据现画**：每米 12 像素，依次画柏油底色、人行道边、各类街区的地面（公园枯草、停车位划线、广场地砖、室内地砖）、街道黄色虚线、安全屋地板和出口警示框，最后叠加噪点、污渍、裂缝。第三区额外加绿色辐射斑，第四区加血迹。
- 粒子和特效用的柔光点、烟雾、血迹贴花、光圈、光柱渐变。

### 3.2 模型（`render/meshes.ts`）

- **丧尸**：用盒子和球拼出来，按部位上顶点色（衬衫、领带、皮肤、裤子……）。四种丧尸外形区分明显：社畜（白衬衫红领带）、头铁（更壮，戴铁桶头盔）、跑得快（红色运动服、身体前倾）、吐口水（鼓胀的黄绿色肚子、发光的嘴）。每个顶点额外记录一个「部位编号」（左腿、右腿、左臂、右臂）。
- **行走动画在着色器里完成**：所有同类丧尸共用一个实例化网格（一次绘制几百只），通过注入 `onBeforeCompile` 的顶点着色器，根据每只丧尸的步伐相位把腿绕髋部、手臂绕肩部旋转；片元着色器再叠加受击闪白和精英变异光晕（黄/橙/红）。
- **尸体**：丧尸死后不立刻消失，而是用同一个实例化网格画成向后倒下、1.2 秒后慢慢沉入地面。
- **玩家**：防护服角色，有防毒面具、发光护目镜、背后氧气瓶；防护服颜色随等级变化（黄 → 橙 → 青 → 蓝紫 → 金），脚下有一个发光圆环，方便在尸群里找到自己。
- **队友**（第2版）：同样的防护服角色，按队友的数据摆出走路、开火后坐、换弹、倒地的姿势，手上是队友当前的枪；脚下光环和护目镜用标识色（青、橙、粉、绿）区分，头顶有名字和血条。
- **防护服柜**（第2版）：安全屋顶部中间的玻璃柜，里面的人台穿着下一阶防护服（颜色就是那一阶的颜色）并缓慢转动，顶部灯条闪烁；拿走后人台消失，灯条变暗。
- **枪械**：由 `GunLook` 数据生成枪身、枪管、弹匣或弹鼓、枪托、瞄准镜和稀有度色条，拿在双手上，也用作地上的掉落物。
- **Boss**：约 3 米高的血肉巨人，背上有骨刺、眼睛发光，四肢分组以便做蓄力、冲刺、投掷、眩晕的姿态动画。
- **曼巴僵尸**（第3次调整）：同一套骨架换成深紫色皮肤、金色球衣和紫色条纹，青色发光的眼睛，放大 1.12 倍，背后拖着一条 7 节的蛇尾（逐节摆动）。激光是两层加法混合的光带（紫色外晕 + 白色内芯），冲击波是向外扩散的青色光环。
- **医疗箱**（第3次调整）：防护服柜右侧的白色急救箱，正面和顶部有红十字，下面是金属底座，带一盏淡红色的灯。
- **场景物件**：车辆残骸（6 种颜色）、枯树、路障、油桶（辐射桶带绿光）、碎石堆（每堆按编号随机生成形状）、沙袋、路灯、长椅、轮胎、骨头、路锥、喷泉、看台、床等，同类物件合并或实例化以减少绘制调用。

### 3.3 光照与氛围（`render/renderer.ts`、`config.ts` 的调色板）

- 每个区域一套调色板：第一区「灰烬街区」暖灰，第二区「锈蚀工业带」铁锈橙，第三区「沉默医院区」辐射绿，第四区「血色中枢」暗红，第五区「尸王广场」紫色，第六区「隐秘核心」深蓝灰配金色点缀（第3次调整）。
- 半球光做环境补光；方向光投射阴影，阴影相机跟随镜头焦点并对齐纹素，避免移动时阴影闪烁；朝瞄准方向打一束手电光；枪口火光、爆炸光、路灯和火堆用固定数量的点光源池（每 0.4 秒把最近的几盏分配给场景光源），避免光源数量变化导致着色器重编译。
- ACES 色调映射，第2版的「场景整体亮度」就是调这里的曝光；高画质开启泛光（Bloom）；场景雾隐藏远处地图边界；空中飘落灰烬粒子。
- 第2版镜头跟随「关注点」：平时是自己，阵亡观战时是队友。

### 3.4 特效与界面图标

- **粒子**（`render/particles.ts`）：在 CPU 上模拟，用 Points 加自定义着色器绘制，分加法混合（火花、火焰、枪口闪光、电弧）和普通混合（烟、血）两组；画质越低粒子越少。
- **2D 叠加层**（`render/overlay.ts`）：伤害数字、拾取提示、准星（两侧弧线显示主副手换弹进度）、屏幕边缘的方向箭头、精英血条、倒计时、连杀。第2版加入：队友名牌与血条、拉起进度圆环、倒地队友的红色方向箭头（带名字和距离）、屏幕上方的提示（暂停、等待队友、关门倒计时、倒地、观战）。
- **界面图标**（`ui/icons.ts`）：枪的侧视剪影按真实数据画；每种子弹有独特图形（炸弹、火箭、锯片、毒雾、奇点漩涡、闪电符号等）；逻辑模块画成芯片；道具各有造型。
- **闪耀 / 虹彩**（第2版，纯 CSS 动画，不需要重新画图标）：闪耀是一道斜着扫过的高光加一个闪烁的四角星；虹彩是图标色相持续旋转、外框颜色在彩虹色之间循环，名字用流动的彩虹渐变文字。背包格子、枪的槽位、HUD 小槽位、商店、拖拽中的图标、提示框标题都会显示。射出的虹彩子弹在场景里颜色随时间流转，闪耀子弹更亮，并带有拖尾。

### 3.5 字体（第2.1版；第3次调整加入 NoitaPixel）

界面换成像素风字体，贴合低多边形、废土的画面风格：

- **第3次调整**：数字、英文字母和 ASCII 符号换成策划提供的 NoitaPixel，汉字仍是 Fusion Pixel。合并方法见 1.9：Noita 的 1 像素 = Fusion 的 2 像素，下移 1 像素，`~` 除外。数字（10×12 像素）与汉字（约 11×11）高度相当，字宽也接近一个汉字，所以 HUD 里的长文字（枪名、按键提示）重新排了版。所有字号统一为 12 的倍数（9~15px 改为 12，17~22px 改为 24），两种字形都落在整像素上。NoitaPixel 的版权属于 Nolla Games，没有附带开源协议。

- 选用 [缝合像素字体 Fusion Pixel Font](https://github.com/TakWolf/fusion-pixel-font) 的 12px 比例宽度简体中文版。它是开源的中文像素字体（SIL OFL 1.1，内部还合并了方舟像素字体、俐方体 11 号、Galmuri 的字形，各自的协议一起放在 `assets/fonts/LICENSES/`），汉字覆盖完整，同时带有拉丁字母和数字。
- 原始字体有 7 MB，先用 fontTools 裁成 GB2312 常用字范围（约 8200 个字符，1.5 MB）作为仓库里的母版，构建时再按游戏实际用到的约 1200 个字符裁剪，最终只有约 42 KB。
- 像素字体的设计尺寸是 12px，所以标题、横幅、倒计时、伤害数字等主要字号改成 12 的倍数（12、24、36、48、72、96），画面上的像素点最整齐；同时关闭浏览器的伪粗体（`font-synthesis: none`），避免把像素笔画糊在一起，强调改用颜色。
- 画布上的文字（伤害数字、名牌、提示、小地图）也统一使用这款字体；缺字时（例如玩家名字里的生僻字）自动回退到系统字体。

### 3.6 测试中修过的画面问题

整体太暗 → 提高半球光、调低太阳光并抬高太阳角度；枯树投下大片纯黑影子 → 枯树不投影、树皮调亮；精英光晕盖住整个模型 → 光晕强度降到原来的约三分之一；玩家在尸群里看不到 → 加脚下光环、换掉和社畜衬衫相近的白色防护服；子弹发光像大米粒 → 收细并降低亮度；Boss 死后冲刺预警线残留 → 修复。第2版：主菜单「联机游戏（局域网 1~4 人）」按钮在小窗口里折行，缩短为「联机游戏（局域网）」。第2.1版（用户反馈）：拖动闪耀 / 虹彩子弹时，拖拽图标的方框变得很宽；闪耀的特效断断续续（见 5.3）。

## 4. 音乐与音效

全部用 WebAudio 实时合成（`src/audio/audio.ts`），没有任何音频文件。

### 4.1 音效

- **基础构件**：一段 2 秒的白噪声（反复使用）、各种波形的振荡器、带频率扫动的滤波器、指数衰减包络；总线末端接一个压缩器，防止多个声音叠加时爆音。
- **配方举例**：
  - 手枪 = 带通噪声短促爆破 + 下滑方波；霰弹 = 低通宽频噪声 + 低频；激光 = 锯齿波快速下扫；火箭 = 带通噪声 + 低频冲击；
  - 爆炸 = 从 3 kHz 扫到 60 Hz 的噪声 + 90 → 28 Hz 的正弦低音；
  - 丧尸低吼 = 锯齿波经窄带通滤波、音高缓慢下滑；
  - 金币 = 两个上行方波音；拾取 / 增益 / 祭坛 = 琶音；门 = 低沉噪声隆隆声 + 结尾撞击。
- **空间感**：按声源与听者的距离衰减，按左右偏移做立体声声像。听者平时是自己，观战时是被观战的队友。
- **队友枪声**（第2版）：复用自己枪声的合成配方（抽成 `shotSound`），音量降到约四分之三并按距离衰减、做声像，同一种枪声最短间隔 50 毫秒，避免四个人同时开火时太吵。
- **防刺耳**：每种音效有最短间隔，同时发声数量有上限（几百发子弹同时命中时也不会炸耳）。
- **第3次调整**：曼巴的激光（持续 4 秒的高频锯齿嗡鸣 + 低频方波共振）和冲击波（低通噪声轰鸣 + 下滑正弦低音）。
- **环境声**：盖革计数器的咔嗒频率随辐射等级上升；生命低于 30% 时有心跳声。

### 4.2 程序化音乐

- **调度器**：每 25 毫秒检查一次，把未来 120 毫秒内的音符精确排到 AudioContext 时间轴上，节奏不受画面卡顿影响。
- **曲目用数据描述**：BPM、根音、每小节和弦、各声部 16 步节奏串（如底鼓 `x...x...x...x...`，`r/f/o` 表示贝斯弹根音 / 五度 / 八度）。
- **音色**：底鼓（正弦音高骤降）、军鼓（带通噪声 + 三角波）、踩镲（高通噪声）、通鼓、锯齿贝斯（滤波器包络）、双锯齿失谐铺底（Pad）、方波拨弦琶音、FM 合成的钟声。
- **曲目**：
  - 主菜单：慢速小调铺底 + 稀疏钟声旋律；
  - 探索：每个区域一首，区域越靠后越快、层次越多（第二区开始加入琶音和更密的踩镲，第三区起底鼓加花）；
  - 安全屋：76 BPM 的七和弦琶音，放松；
  - Boss 战：146 BPM，十六分音符贝斯、加花通鼓；
  - 胜利 / 失败：短小的上行 / 下行乐句（联机时自己阵亡转为观战也会播放失败乐句）。
- 切换曲目时旧曲淡出 1.2 秒、新曲淡入 1.5 秒。

### 4.3 限制

我无法实际听到声音，只能确认 AudioContext 能正常启动（状态为 running）、控制台没有报错，音色好不好听需要人工试听后再调整。

### 5.2 自动游玩 AI 的演进（`src/debug/bot.ts`）

AI 是平衡测试的基础，它本身也迭代了好几版：

1. 朝安全屋走、打最近的敌人、看到道具就去捡 → 在目标之间来回摇摆，频繁冲进尸群。
2. 「危险场」：评估 16 个方向的危险度 → 太胆小，会被逼进地图角落困死（轨迹里能看到坐标停在 (2, 3) 附近）。
3. 加入「开阔度」评分，避开墙角 → 仍然逐帧左右抖动、原地不动。
4. 加入方向惯性 → 改善，但仍然不推进。
5. 初版最终：目标牵引 + 近距离丧尸排斥（头铁、精英、Boss 权重更高）+ 遇墙旋转找可走方向 + 方向平滑，并避开 Boss 冲刺预警线和落石圈。
6. 第2版：
   - 进安全屋后先去防护服柜拿防护服；
   - 到达目标附近时不再触发「卡住检测」（之前会在出口倒计时中被抖出黄色区域，安全屋要待 30~90 秒，见 5.3）；
   - 联机时去拉起 12 米内倒地的队友（站定后按 F）；
   - 队友在弹道附近时不开火（按到弹道的横向距离判断，射程内随距离放宽）；
   - 避开毒雾、奇点和快要爆炸的炸弹 / 地雷，不在贴脸时打出火箭、炸弹、奇点弹。
7. 第3次调整：
   - 安全屋里先拿防护服，再去医疗箱回满生命；第五区的安全屋先捡净化血清；
   - 第五区在牢大倒下之前不去上锁的安全屋；
   - 按命中半径躲石块，远离冲击波的蓄力圈，像躲冲刺线一样躲激光；
   - 第五、六区的黄色阈值是 0，所以在这两个区只在快到橙色时才用净化血清（否则一进场就会把血清全部用掉）。

经验：AI 的弱点很容易被误判成游戏太难，所以每次出现异常都先打开逐秒轨迹，确认原因是游戏问题还是 AI 问题，再决定改哪边。第2版的「自伤」问题就是这样分辨的：先在模拟里统计自伤来源（毒雾 970、爆炸 283），再逐条追踪事件（`t=73.0 -32.9 blast at dist 3.9 guns=…mine`），才定位到是感应地雷，而不是笼统地降低 5% 这个数值。

### 5.5 联调中遇到的环境限制

- 内置浏览器面板被隐藏或标签页在后台时，页面的 requestAnimationFrame 会暂停，游戏不会实时运行，这时看到的帧率、刷怪数量都不可信，所以性能和战斗测试改为用脚本手动驱动循环。第2版的联机测试正好借这个现象验证了后台保底计时。
- 面板尺寸会变，截图有时只截到页面的一角（第2版设置视口仿真后也出现过），需要调整视口、借助缩放，或者直接读取元素的位置和尺寸来确认布局。
- 无法实时手动操作和亲耳听声音，所以手感、联机时的网络体验和音色仍需要真人试玩确认；只测试了同一台电脑上的两个标签页，没有在两台真实的局域网电脑之间测试。

## 7. GitHub 协作（第4次调整）

- **仓库**：<https://github.com/alone03125/Game4056>（公开）。
- **只能通过 PR 修改 main**：`main` 开启了分支保护——合并前必须有一个批准的审阅，并且必须是代码所有者（`.github/CODEOWNERS` 写的是 `@alone03125`）批准；新的提交会让之前的批准失效；CI 必须通过；禁止强制推送和删除分支。仓库所有者自己不受这些限制，可以直接推送。小组成员被加为协作者后，在自己的分支上提交、再提 PR（不能直接推 main）；外人也可以 Fork 后提 PR。`CONTRIBUTING.md` 面向几乎没用过 GitHub 的组员，从安装 Git、克隆仓库讲到同步、提交、提 PR 和解决冲突。
